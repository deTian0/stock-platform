## 背景

`L` 域是路线图唯一带**门禁**的域。§3.5 的前置写明：

> `L1` 未立项通过前，**禁止开工** `L2` / `L3`。这是对既有红线（`liveTradingEnabled=false`）的
> 显式解禁流程，不是绕过。

红线第 7 条同时写明：**`L1` 未立项前，任何人不得用「完善」为由触碰 `liveTradingEnabled` 与实盘券商代码。**

而 `liveTradingEnabled=false` 在代码里**不是一句声明，是一道硬闸**：`packages/execution/src/stock_platform_execution/profile.py`
的 `validate_simulation_profile()` 会在 `liveTradingEnabled` 不为 `False` 时直接抛 `ProfileBlocked`；
全仓约 **37 个源文件**（research ≈20 / workbench ≈10 / execution 6 / agents 2）与 **21 个测试文件**
（`test_app.py` 26 处断言、`test_all_api_endpoints.py` 20 处断言等）把这一位钉死。

因此 `L1` 的实质是：**在承认上述硬闸的前提下，回答「要不要、以及在什么边界内解禁」。**

用户于 2026-10-10 给出三项前置：**券商 = 华宝证券（国内）**、**资金上限 = 1 万元**、
**合规边界 = 纯模拟盘（暂不入实盘）**。

---

## 决策

### 1. 券商选定：华宝证券（国内）

选定理由：用户既有账户与费率（**佣金 万 0.854 免 5**）；场内 ETF 与 A 股同一账户管理；
无跨境/外汇合规复杂度。**本轮不申请任何量化终端权限。**

**落选候选与原因**（路线图 §3.5 要求的选型记录）：

| 候选 | 落选原因 |
|------|----------|
| 富途 / 其它港美股通道 | 引入跨境与外汇合规复杂度；与现有 A 股持仓/费率不兼容；**资金上限 1 万元**下无意义 |
| 同花顺 | 平台既有 `ths_sim` 为**模拟**通道（ADR `0038`），真机通道未接入且不在本轮边界内 |

### 2. 资金上限：1 万元，**账户总资产口径（含现有持仓）**

- 该 1 万元是**账户全部资产上限**，含现有场内持仓（约 5240 元 ETF + 中国石化 100 股）。
- **可动用额度 = 1 万 − 现有市值**，不得外部追加。
- 任何阶段都不使用融资融券、场外配资或其它杠杆资金（监管报告口径要求披露杠杆来源）。

### 3. 合规边界：**Phase 0 = 纯模拟盘**；本次**不解禁红线**

**关键结论（由资金量决定，不是偏好）**：

- 华宝 `QMT` / `PTrade` 量化终端门槛 ≈ **10 万元**（近 20 个交易日日均证券资产），
  另需 6 个月 A 股实盘经验 + 风险测评 C4/C5；
- **1 万元拿不到终端 → 拿不到券商 API → 程序无法自动发单**；
- 而「程序化交易」的法定定义是「通过计算机程序**自动生成或者下达**交易指令」——
  **人工在券商 APP 手动下单不构成程序化交易，无需向交易所报备**。

所以本阶段**唯一现实且零合规暴露**的路线是 P0：平台只产出信号，不下任何真实委托。

**本次 `L1` 明确不解禁红线**：`liveTradingEnabled` **维持恒 `false`**；`L2` / `L3` **不开工**；
`packages/execution` 的 `ProfileBlocked` 硬闸**保持原样**。

### 4. 三阶段路线与解锁条件

| 阶段 | 名称 | 交易方式 | 报备 | 解锁前置（**须全部满足**） |
|------|------|----------|------|----------------------------|
| **P0**（本次） | 纯模拟盘 | 平台出信号 / 候选 / 买卖建议 → **不接券商**，人工纸面记录 | 无 | 当前即满足（`B5` + `X4` 已就绪） |
| **P1**（未来） | 半自动（信号 + 人工下单） | 平台出信号 → **人工在券商 APP 手动下单** | **免报备** | ① 用户显式复议并更新本 ADR；② **华宝客户经理书面确认**「人工下单不构成程序化交易」；③ 名义本金 / 单笔上限 / 熔断规则生效；④ 模拟盘累计 ≥ 30 个交易日且与回测口径一致 |
| **P2**（未来） | 全自动（`QMT`） | 平台经 `QMT` / `xtquant` **自动下单** | **必须报备**（先报告后交易，券商代办） | ① P1 稳定运行 ≥ 60 交易日；② 账户近 20 交易日日均资产 ≥ 10 万元；③ 6 个月 A 股经验 + 风险测评 C4/C5；④ 华宝量化白名单开通 + 完成程序化交易报备；⑤ 通过「远离高频线」与「避开四类异常交易」自检；⑥ **独立 ADR 复核并显式 Accepted** |

P1 的「免报备」**不是终局判断**：`自动生成` 四字在监管口径上留有解释空间，故 P1 解锁前置第 ②
项要求**券商书面口径**，不接受「我觉得不算」。

### 5. 解除红线时的**影响面清单**（P1/P2 前置，本次不改）

若未来解禁，须同步处理的清单（**这是 `L1` 交付的「影响面清单」**）：

| 层 | 位置 | 需做什么 |
|----|------|----------|
| 硬闸 | `execution/profile.py::validate_simulation_profile` | 放开前须新增**显式环境开关**（而不是删掉断言），并保留 `SIMULATE` 默认 |
| 契约 | `execution/contracts.py`（`live_trading_enabled: bool = False`） | 改为可按阶段注入，并附阶段标识 |
| 报告封套 | `research` ≈20 个模块的 `"liveTradingEnabled": False` | 逐处改为读环境，**不允许**留第二份真相 |
| Workbench | `openapi_models.py`（≈26 个响应模型硬置 false + 11 个可选位）、`routes/{research,paper,broker,ops,market,settings}.py`、`app.js` | 响应字段与 UI「实盘」指示同步改为可读真实值，且异常态仍要显红 |
| agents | `llm_debate.py` / `deep_llm_graph.py` | 同上 |
| 文档 | `README.md`、`docs/upstream-archive.md`、`docs/plans/dual-line-responsibility.md`、`docs/ROADMAP.md`、路线图红线第 7 条、3 份含 `liveTradingEnabled` 的契约 | 逐处更新「恒 false」措辞 |
| 测试 | 21 个测试文件（含 `test_paper_safety.py` / `test_broker_port.py`） | 断言从「恒 false」改为「按阶段允许 + 默认仍 false」 |

### 6. 失败回滚方案

| 阶段 | 回滚动作 |
|------|----------|
| P0 | **无资金风险**。停跑即回滚；模拟数据本地留存 |
| P1 | 平台**本就没有自动下单路径**，故回滚 = 停发实盘建议；已成交持仓按 `rules.py` 退出策略**人工**执行 |
| P2 | 订单状态机逐态处理（接受 / 部成 / 全成 / 撤单 / 拒单 / **状态未知**）；**「状态未知」一律置人工介入**；每日对账；回滚 = 关闭 QMT 策略 + 撤回 API 权限 + 持仓转人工 |

**共性铁律**：任何阶段都**不允许**在无显式人工确认下发生「程序自动下单」—— 除非该阶段的 ADR 明确解锁。

### 7. 版本映射建议

`L1` 收口**建议 `v4.1.4`**（S 域 minor 顺延；本里程碑只增治理决议与契约，**不解除任何能力**）。
**`v5.0.0` 保留给「真正解除红线」的那次**（即 P1/P2 立项复核）。

这是对路线图 §5「L → `v5.0.0`–`v5.0.2`（major，解禁实盘红线）」的**建议修订**：
既然本次不解禁，「major / 解禁红线」的语义与内容不匹配，故顺延。**需用户一并确认。**

## 后果

**正面**

- 决策留痕：券商、资金、合规边界、三阶段解锁条件、影响面、回滚方案全部落到纸面，
  未来任何「要不要上实盘」的讨论有唯一依据。
- **零合规暴露**：P0 不接券商、不下真实委托 ⇒ 不触发报告义务，也不进入异常交易监控视野。
- 硬闸不动：`ProfileBlocked` 与全仓 ≈58 个文件的 `liveTradingEnabled=false` 断言**零改动** ⇒ 零回归风险。

**代价 / 风险**

- **能力闲置**：平台已具备 paper 券商与纸面闭环，但**全部**实盘能力继续封存；
  `L2` / `L3` 继续 blocked。
- **「免报备」结论依赖券商书面口径**：P1 若拿不到书面确认，则须按「需报备」重新评估。
- **1 万元本金的统计意义弱**：单笔 ≤ 2000 元、A 股 100 股一手约束下，部分高价股直接不可买，
  模拟结果对实盘的**可迁移性有限**；这一点必须在不夸大结论的前提下如实写入运行记录。
- 版本映射与路线图 §5 出现**偏离**，需在路线图「修订记录」留痕。

## 备选方案

| 方案 | 为何不选 |
|------|----------|
| 直接把 `L1` 置 `Accepted` 并解禁红线，走 `QMT` 全自动 | **1 万元达不到华宝 10 万终端门槛**，物理上不可行；且会立刻引入报备、异常交易监控、差异化收费等全部合规义务 |
| 走「半自动（P1）」作为本次收口 | 用户明确选择**暂不入实盘**；且 P1 仍依赖券商对「人工下单是否构成程序化交易」的书面确认，本轮不阻塞在第三方回复上 |
| 不立 `L1`，继续只做回测 | `L1` 已列为关键路径下一站；不立项则「要不要实盘」永远悬空，且红线第 7 条会长期缺少决议依据 |
| 换一家低门槛券商（如宣称 10 万即可的其它券商） | 门槛量级相同（均为 10 万档），换券商不解决本金不足；且用户已有华宝账户与费率 |
| 用「模拟盘 + 条件单」绕过（APP 零代码自动化，0 门槛免报备） | 该路径**不需**平台参与下单，平台价值退化为「看一眼信号」；属未来可评估的第 4 条路，不在本 ADR 边界内 |

# 0082 — 盘后当日行情台账（开/收/涨跌 + 量化归因）

- Status: Accepted
- Date: 2026-10-23
- Supersedes: —
- Related: ADR 0033（推荐绩效台账 `A4`）、ADR 0057（命中追踪 `A3`）、
  ADR 0058（market.db 只读真相源）、ADR 0071（`report_html` 单点）、
  ADR 0078（收益归因，**反向**：那是「为什么这段时间亏」，本 ADR 是「今天为什么涨跌」）

## 背景

盘后台账（`A3` 命中追踪 + `A4` 绩效台账）回答的是**账户层面**的问题：赚了多少、命中几次。
用户实际看盘时问的是**另一个问题**：

> 今天这只**开盘多少、收盘多少、涨了还是跌了、为什么**？

这三个字段此前**一个都没有出口**：

| 想知道 | 平台现状 |
|---|---|
| 收盘 / 涨跌幅 | 有（`daily_price.close` / `pct_chg`），但**没有一个报告按当日列出** |
| 开盘 / 最高 / 最低 | **完全没有**：引擎 `daily_price` 只有 `code/date/close/pct_chg/vol/amount` 五列 |
| 涨跌原因 | 没有；且平台**无新闻 / 公告 / 龙虎榜数据源** |

## 决定

新增报告项 **`A6_day_quote`**（当日行情与涨跌归因）与单点
`packages/research/src/stock_platform_research/day_quote.py` + CLI `stock-platform-day-quote`。

### 1. 四价分工：收盘走引擎，开/高/低走外部源 + 缓存

| 字段 | 来源 | 为什么 |
|---|---|---|
| `close` / `prevClose` / `volume` / `ma20` | **引擎 `market.db`** | 与主链同一份当日截面，口径不会漂 |
| `open` / `high` / `low` | **外部日线**（东财 `kline/get`，经 `em_get`） | 引擎库无这三列，且**不允许写库**（ADR 0058） |
| 缓存 | `data/quotes/ohlc-<asof>.json` | 同日复跑**零网络且结果一致**，也让报告可离线复核 |

外部源失败 → 该列输出 `—`、归因**降级**为「量能 + 相对基准 + 位置」，
报告顶部标注降级原因。**绝不补零、绝不猜。**

### 2. 涨跌幅一律**自算**，不读 `daily_price.pct_chg`

`pct_chg` 在引擎库里是**混合尺度**（股票多为小数、ETF 多为百分点，见
[`pct_scale`](../../packages/research/src/stock_platform_research/pct_scale.py)）。
本报告统一用 `close / prev_close − 1`，好处是：

- 跨资产（股票 / ETF）天然一致，不需要尺度投票；
- `gap` / `intraday` / `amplitude` 共用同一分母，四价之间不会互相矛盾。

### 3. 「涨跌原因」= **量化归因**，并显式声明不是消息面

本平台没有新闻 / 公告源。任何「因为某消息」的表述都是编造，因此归因**只允许**由四轴机械组合：

| 轴 | 输入 | 标签示例 |
|---|---|---|
| **分时形态** | `gap` / `intraday` / `high` / `low` | 高开低走、低开高走、冲高回落、探底回升、窄幅整理、单边走强/弱 |
| **量价** | `vol / 前 20 日均量`（**不含当日**） | 放量上涨、放量下跌、缩量下跌、量能常态 |
| **相对基准** | `pct − 基准当日 pct` | 强于基准 / 随基准 / 弱于基准 |
| **位置** | `close vs MA20` | 站上20日线 / 20日线下方 |

payload 顶层固定携带 `attributionKind="quantitative"`，报告顶部固定印
「平台无新闻/公告源，故不含且不编造消息面原因」。

量能分母**刻意排除当日**：否则当日爆量会把自己摊薄（`vol_ma20` 含当日 ⇒ 比值被系统性压低）。

### 4. 覆盖范围 = 当日选股 + 持仓，基准单独成行

- `pick`：asof 归档 brief 的 picks（当日**实际下发**的榜单，不重算）；
- `holding`：`data/holdings.json`（缺失则空，fail-open，不阻断）；
- `benchmark`：单独一行，**不参与**涨跌家数 / 平均涨跌统计。

### 5. 已知缺陷（本 ADR 记录，不在本期修）

`A4` 与 `A6` 的基准都由 `resolve_benchmark_symbol()` 给默认值 `000905`。
**引擎库里的 `000905` 是「厦门港务」这只个股，不是中证500指数**（实测：

```
000905 -> '厦门港务'   # symbol_master
000905.SZ close=8.26  # 不是 ~5000 点的指数点位
```

连带后果：`A4.avgAlpha`、`A6.dayAlpha` 都是**相对该个股**的超额，**不能读作指数超额**。
另经实测，`astock_http.get_daily` 对 `000001.SH` / `000905.SH` 会按代码规则回落成深市个股
（后缀被 `normalize_symbol` 剥掉），**当前拿不到可靠指数序列**。

因此本期**不改基准口径**（改它会断掉历史台账可比性），而是在 `A6` 报告顶部**强制打印**
`benchmarkWarning`，把这件事显式化。修复（provider 支持强制市场后缀 + 基准口径迁移）
另立里程碑。

## 备选方案（未采纳）

| 方案 | 为什么不要 |
|---|---|
| **把开/高/低写进引擎 `market.db`** | 违反 ADR 0058（只读真相源 + 禁写）；且引擎是上游产线，平台侧不该回写 |
| **用 `pct_chg` 反推开盘价** | 数学上做不到：`pct_chg` 只编码收盘对昨收，开盘信息不在其中 |
| **把归因塞进 `A4` 绩效台账** | `A4` 是**已结算样本**的统计闭环（5 日窗口），本报告是**当日单根 K 线**；混在一起会让「今天」和「这段时间」两个口径互相污染 |
| **接新闻 / 公告源做「真原因」** | 平台无该数据源，且引入后需要情感/事件抽取与归因标注，属于独立能力域；先量化、后消息面 |
| **每只都联网抓实时** | 会破坏「同日复跑结果一致」；故走缓存，首次抓、之后读 |

## 后果

- **正面**：盘后台账第一次能回答「开多少、收多少、涨跌多少、大致为什么」；
  四价与归因都是**可复算**的机械口径，不是叙述；
  基准缺陷被显式化（此前 `avgAlpha` 的失真无人察觉）。
- **代价**：首次跑需要一次外部日线请求（~14 只标的，秒级），之后走缓存；
  引擎库无指数的限制仍在，全市场广度（涨跌家数全口径）暂时给不了。
- **风险**：外部源不可用 → 只有收盘价，形态轴失效（已降级并标注）；
  停牌 / 新股（不足 20 根）→ `volRatio` / `vsMa20` 为 `None`，不参与标签；
  跨多日停牌的 `pct` 会含多日累计，`staleBars` 标记并在标签里写「当日无K线」。
- **测试**：`packages/research/tests/test_day_quote.py`（四价派生、量能分母排除当日、
  MA20 窗口门槛、stale 标记、六类形态、相对基准三档、汇总去重与基准不入统计、渲染小节与警示）。

## 不做的事

- **不写库**（引擎 / 平台 SQLite 均只读）。
- **不改 `A4` 的基准口径**（见 §5）。
- **不做消息面归因**。
- **不做实时**：口径是 asof 当日收盘的**单根 K 线**。

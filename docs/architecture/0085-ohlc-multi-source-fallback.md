# ADR 0085：盘后「开盘/收盘/涨跌」的多源兜底（东财 → 腾讯 → 新浪）

- 状态：已采纳
- 日期：2026-10-30
- 里程碑：`v4.13.5`
- 关联：[0082 当日行情台账](0082-day-quote-attribution.md) · 契约 [`day-quote`](../contracts/day-quote.md)

## 1. 背景

盘后简报的「开盘(T) / 收盘(T) / 涨跌(T)」三列只有一个数据来源 —— 东财
`push2his/kline/get`（经 `em_get`）。`market.db` 的 `daily_price` 没有
open/high/low 三列，且当日 K 线要等 **18:30 回补**才入库，所以 15:30 那一跑
**只有东财一条命**。

`v4.13.4` 已经把「部分失败」扛住了（分批 + 换断路器实例重试 + 3 轮补齐），
但那个修复的前提是**东财还在回答，只是偶尔少回几只**。2026-10-30 15:31 实测
的是另一种故障：东财**整体不可达**（`CircuitOpenError`，断路器打开），三次重试
全部落空 —— 分批、重试、引擎库兜底（当日无 K 线）**三条路同时失效**，三列又是 `—`。
连续两个交易日（10-29、10-30）同一症状复发，说明是结构性问题而非偶发。

## 2. 决策

给「当日一根 K 线的 OHLC」引入**多源链**，而不是继续在东财内部加固：

```
东财 push2his/kline/get（主源，含完整历史）
  └─ 腾讯 qt.gtimg.cn（批量快照，GBK 文本）
       └─ 新浪 hq.sinajs.cn（批量快照，GBK 文本）
            └─ 都没有 → 留 —，并在「数据备注」写明三源均失败
```

新增 `stock_platform_providers.snapshot`：

| 项 | 取值 |
|---|---|
| 入口 | `fetch_day_snapshot(symbols, day, *, get_text=None)` → `(rows, note)` |
| 解析器 | `parse_tencent_snapshot` / `parse_sina_snapshot`（纯函数，无网络，可单测） |
| 批量粒度 | `SNAPSHOT_CHUNK = 50` 只/请求（URL 长度可控） |
| 字段 | 腾讯 `~` 分隔：3=现价、5=今开、33=最高、34=最低、30=时间戳；新浪 `,` 分隔：1=今开、3=现价、4=最高、5=最低、30=日期 |
| 失败语义 | 任何异常 → `{}` + `note`，**永不抛出** |

接线点只有一处：`day_quote_cli._fetch_ohlc`。东财轮次结束后仍有缺口（或整轮颗粒
无收）时调 `_snapshot_fill`，把缺口交给快照；`quotes.load_ohlc`、`A6` 行情台账、
盘后简报因此**全部自动获得兜底**，不需要各自改。

## 3. 硬约束

1. **日期必须相等**。快照只接受 `trade_date == quote_date` 的行。厂商在收盘后
   仍会返回**上一个交易日**的完整 K 线，若不校验就会把旧收盘当成当日收盘，
   涨跌恒等于 0 —— 比留 `—` 更糟（`v4.13.4` 的引擎库兜底同样刻意避开
   `quote_date == asof`，是同一条原则）。
2. **停牌整行丢弃**。`open <= 0` 或 `close <= 0` 视为无效，绝不补零。
3. **不经 `em_get`**。腾讯/新浪属非东财端点，必须走自己的 session（与
   `astock_http` 里的新浪财报 / 复权因子路径同一约定）；混进 `em_get` 会污染
   断路器与限流口径。
4. **东财优先**。快照只在东财缺席时补位，`setdefault` 语义保证不覆盖东财已拿到的行。
5. **换源要留痕**。全部标的都靠快照救回时，「数据备注」写明
   `东财不可达（…），N/M 只改用腾讯/新浪当日快照`；部分缺口则由东财填的部分静默
   （此时对外没有降级）。错误摘要只取首行并截断 60 字 —— `CircuitOpenError` 原话能写满一屏。
6. **不新增写库**。快照行照旧落 `data/quotes/ohlc-<date>.json`，因此同一天复跑
   零网络（第二、三次渲染不再请求任何源）。

## 4. 为什么不选其它方案

| 方案 | 否决理由 |
|---|---|
| 只加重试/加长超时 | 断路器打开期间重试是空转；10-30 三次重试 0 命中 |
| 等 18:30 回补后重渲染 | `daily_price` 无 open/high/low，回补也补不出开盘价 |
| 用前一日收盘冒充当日 | 涨跌恒 0，污染 A6 归因与命中追踪的次日窗口 |
| 引入新依赖（akshare/baostock） | 腾讯/新浪是裸 HTTP + 正则，零依赖即可；仓库亦不许随意 pip |

## 5. 验证

- 真机 2026-10-30 15:38：东财仍 `all daily fetches failed`；腾讯
  `v_sh600854` 与新浪 `hq_str_sh600854` 均返回 `open 4.21 / high 4.33 / low 4.15 / close 4.18`，
  两源一致（`test_tencent_and_sina_agree` 锁死这条）。
- 重渲染 `data/digests/2026-10-30-post.md`：Top10 / ②A / ②B 三张表的
  「开盘/收盘/涨跌」**21/21 全部有值**，数据备注记录「21/21 只改用腾讯/新浪当日快照」。
- 单测：`packages/providers/tests/test_snapshot.py` 16 例（真实 payload 解析、跨日拒收、
  停牌丢弃、北交所前缀、源降级顺序、部分合并、全失败不抛、四板前缀参数化）+ `test_quotes.py`
  新增 4 例并改写 1 例（东财全灭时换源、只对缺口请求快照、兜底异常不外泄、快照行入缓存）；
  `test_quotes.py` 增加 autouse fixture 打桩 `_snapshot_fill`，**单测绝不联网**。全量 1322 passed。

## 6. 遗留

- 快照只给「当日一根」，没有 20 日均量/MA20 所需的序列 —— 这些仍由引擎库提供，互不冲突。
- 若三源同时不可达（整机断网），三列仍为 `—`。这是**诚实降级**，不造假数据；
  此时「数据备注」会写明三源均失败。
- 无开盘价的次日，「涨跌」列留空而非等于 0，`A6` 的 `gap`/`intraday` 同样留 `null`。
